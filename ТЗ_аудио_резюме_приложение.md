# Техническое задание: консольное приложение для извлечения аудио и резюмирования видео

## 1. Назначение и общая идея

Консольное приложение для Windows, запускаемое одним файлом (умный батник), которое
позволяет пользователю выполнить одну из двух задач над видео- или аудио-источником:

1. Извлечь и сохранить аудиодорожку (MP3).
2. Получить структурированное текстовое резюме содержания.

Источником является локальный аудио/видео файл либо ранее сохранённый транскрипт.
Онлайн-источники (ссылки YouTube/Vimeo/URL) НЕ поддерживаются — приложение работает
полностью офлайн на этапе ввода и транскрипции; сеть нужна только облачному API
резюмирования. Приложение работает в интерактивном режиме через красочное
консольное меню и не закрывается после операции, а возвращается в главное меню до
явного выхода пользователем.

Документ описывает ТОЛЬКО поведение и процессы продукта. Выбор языка программирования,
библиотек, инструментов транскрипции, способа генерации PDF и прочего стека —
полностью на усмотрение реализующего агента, при условии соблюдения описанной логики.

## 2. Запуск и режим работы

- Приложение запускается одним файлом (батник), который при первом запуске
  самостоятельно подготавливает рабочее окружение и устанавливает зависимости, а при
  последующих — просто запускает приложение.
- Интерфейс — интерактивная консоль с красочным, наглядным главным меню.
- Работа построена как цикл: после завершения операции приложение возвращается в
  главное меню. Выход — только по явной команде пользователя (отдельный пункт меню).
- Ведение логов/истории операций НЕ требуется. Каждый запуск независим.

## 3. Главное меню и навигация

Главное меню должно быть визуально оформленным (заголовок, разделители, понятные
пункты). Первичный выбор пользователя:

1. Обработать локальный файл (аудио/видео).
2. Создать резюме из сохранённого транскрипта.
3. Настройки.
4. Выход.

После выбора источника приложение запрашивает ввод (путь к файлу или выбор
транскрипта) и переходит к меню выбора действия.

## 4. Поддерживаемые источники

- Локальные файлы: основные распространённые аудио- и видео-форматы
  (например MP3, WAV, M4A, MP4 и аналогичные ходовые). Поддержка экзотических форматов
  не требуется.
- Сохранённые транскрипты: текстовые файлы из папки `output/transcripts/` (см. раздел 9),
  а также транскрипт по введённому/вставленному пути.
- Онлайн-источники (ссылки) НЕ поддерживаются.
- Если источник некорректен/недоступен/неподдерживаем — понятное сообщение об ошибке и
  возврат в главное меню (см. раздел 11).

## 5. Доступные действия (развилки)

### 5.1. Если источник — локальный видеофайл
Меню выбора действия:
1. Только извлечь и сохранить аудио (MP3).
2. Только сделать резюме.
3. Сделать и аудио, и резюме.

### 5.2. Если источник — локальный аудиофайл
1. Сделать резюме.
2. (Опционально) Конвертировать в MP3 — только если файл ещё не MP3; результат
   сохраняется в `output/audio/` по той же схеме именования (дата + название).

### 5.3. Если источник — сохранённый транскрипт
Доступно единственное действие:
1. Сделать резюме (без повторной транскрипции), с текущими настройками
   языка/формата/модели и обычным расчётом и подтверждением стоимости.

Примечание: транскрипт строится из звука самого источника (а не из субтитров),
поэтому корректно обрабатываются видео без субтитров.

## 6. Процесс обработки

### 6.1. Извлечение аудио
- Из локального видеофайла извлекается и сохраняется аудиодорожка в формате MP3.
- Извлечённое аудио НЕ удаляется после операции и хранится в отдельной папке
  (см. раздел 9), в том числе когда пользователь запросил только резюме.

### 6.2. Транскрипция
- Для резюме источник сначала транскрибируется в текст локально.
- Поддерживаются как минимум русский и английский языки; язык распознаётся
  автоматически.
- Полный транскрипт ВСЕГДА сохраняется в отдельную папку (см. раздел 9), независимо
  от выбранного действия по резюме.

### 6.3. Резюмирование
- Резюме формируется через облачный API (Anthropic) на основе транскрипта.
- API-ключ берётся из переменной окружения и не хранится в коде.
- Язык итогового резюме по умолчанию русский; меняется в настройках (раздел 10).

## 7. Структура и содержание резюме

Итоговое резюме должно содержать следующие смысловые блоки:

1. Обзор: о чём видео, для кого, общий контекст.
2. Ключевые выводы: маркированный список основных тезисов.
3. Тайм-коды по крупным смысловым блокам: глобальные временные метки больших
   разделов обсуждения (НЕ по каждой фразе/абзацу).
4. Повторяющиеся факты: мысли и факты, к которым автор возвращается.
5. Главная идея: финальный вывод, центральное сообщение материала.

Точные формулировки промпта под суммаризацию подбирает агент; структура выше —
обязательный минимум.

## 8. Обработка длинных материалов (2 ч и более)

- Ограничения по длительности НЕТ — длинные материалы должны поддерживаться.
- Для длинных материалов применяется поэтапная обработка (разбивка на части с
  последующей сборкой итогового резюме), чтобы уложиться в ограничения контекста и
  сохранить качество.
- Способ оптимизации (стратегия разбивки, кэширование промпта, пакетная обработка и
  т.п.) — на усмотрение агента.

### 8.1. Предупреждение и расчёт стоимости
- Перед запуском резюмирования приложение оценивает примерную стоимость операции
  (на основе объёма транскрипта и цены выбранной модели) и показывает её пользователю.
- Запуск резюмирования происходит только после подтверждения пользователем.
- После выполнения приложение показывает фактическую стоимость на основе реальных
  счётчиков токенов из ответа API.

## 9. Файлы, папки и именование

- Все результаты сохраняются в фиксированную структуру папок рядом с приложением.
  Пути к папкам и подпапкам захардкожены.
- Раздельные подпапки по смыслу, как минимум:
  - папка для аудио (MP3);
  - папка для транскриптов;
  - папка для резюме (итоговые документы).
- Именование аудио и транскриптов: по дате и названию ролика/файла.
- Именование документа-резюме: по смыслу содержимого (осмысленный заголовок).
- При совпадении имён файлы не должны молча перезаписываться (добавлять ID).

## 10. Формат вывода резюме

- По умолчанию — PDF.
- В настройках доступен альтернативный формат — Markdown (.md).

## 11. Настройки

Отдельный пункт главного меню «Настройки» позволяет менять:

1. Язык итогового резюме (по умолчанию русский).
2. Формат вывода резюме (PDF по умолчанию / Markdown).
3. Выбор модели резюмирования — ЖЁСТКИЙ выбор по точному имени модели, три
   фиксированных варианта по тирам: экономичный, сбалансированный, флагманский.

### 11.1. Управление версиями моделей (важно)
- Точные имена моделей и их цены за токен хранятся в конфигурации (НЕ зашиты в логику),
  чтобы при выходе новой версии или снятии старой можно было обновить одну запись.
- Если API возвращает ошибку о снятой/неизвестной модели (деприкейт), приложение
  показывает понятное сообщение и предлагает пользователю выбрать другую модель в
  настройках, а не завершается аварийно.

## 12. Обработка ошибок

Любая ошибка должна сопровождаться понятным человекочитаемым сообщением и возвратом
в главное меню (без аварийного завершения). Минимальный перечень обрабатываемых
ситуаций:

- Неверный путь к локальному файлу или неподдерживаемый формат.
- Отсутствие интернет-соединения на этапе резюмирования (вызов облачного API).
- Отсутствие API-ключа в окружении.
- Превышение лимита/исчерпание баланса на стороне API.
- Снятая/неизвестная модель (см. 11.1).
- Отсутствие необходимого внешнего компонента для конвертации аудио.

## 13. Нефункциональные требования

- Понятные сообщения о прогрессе на каждом этапе (скачивание, транскрипция,
  резюмирование), так как обработка длинных материалов небыстрая.
- Приложение рассчитано на персональное использование на Windows; кроссплатформенность
  не требуется.
- Конфигурация (имена моделей, цены, язык, формат) должна быть легко редактируемой.

## 14. Возможные будущие доработки (вне текущего объёма)

Не входят в текущую версию, но архитектуру желательно не закрывать для них:

- Поддержка дополнительных источников (другие видеоплатформы, подкасты).
- Пакетная обработка списка ссылок/файлов за один запуск.
- Экспорт резюме в дополнительные форматы (DOCX, HTML).
- Локальная (офлайн) суммаризация как альтернатива облачному API.
- Сохранение пользовательских пресетов промптов под разные типы контента.
- Графический интерфейс поверх той же логики.

## 15. Критерии готовности

Приложение считается готовым, когда корректно отрабатывают все сценарии:

- Локальный видеофайл → только аудио (MP3 сохранён в нужную папку).
- Локальный видеофайл → только резюме (включая видео без субтитров).
- Локальный видеофайл → аудио + резюме.
- Локальный аудиофайл → резюме (+ опциональная конвертация в MP3, если ещё не MP3).
- Сохранённый транскрипт → резюме без повторной транскрипции.
- Корректная работа на русском и английском материале.
- Предупреждение о стоимости и подтверждение перед длинным резюмированием.
- Смена языка, формата вывода и модели через настройки.
- Понятные сообщения и возврат в меню при всех ошибках из раздела 12.
