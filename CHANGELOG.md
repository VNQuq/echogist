# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/);
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [2.0.0] — 2026-06-27

> Ломающий релиз. Поменялась форма `Summary` (старые `output/summaries/raw/*.json`
> от v1.x не загрузятся), удалён весь путь map-reduce/группировки/одиночного прохода.
> Принцип «верность > полнота» провалидирован на платном 3-часовом RU-прогоне.

### Изменено (BREAKING)

- **TD-16 v2: прямой синтез транскрипта вместо map-reduce.** Принцип развёрнут на
  «верность > полнота»: транскрипт — источник истины, читается НАПРЯМУЮ, в один проход. Он
  делится на K непрерывных НЕперекрывающихся фаз (`chunk.plan_phases`; K вычисляется по
  размеру, короткий материал = K=1), каждая фаза одним вызовом синтезируется в верную прозу
  (`synthesize_summary`), последовательно и только-вперёд: фаза видит прежние заголовки и
  «хвост» прозы предыдущей фазы как контекст «не повторять». Пасс reconcile (только при K>1)
  пишет title/core_idea/main_themes из прозы фаз, не перечитывая транскрипт.
- **Удалены map-reduce, иерархическая группировка и одиночный проход** (TD-5/TD-15) со всем
  кодом: `summarize`/`summarize_chunked`/`group_summary`, схемы `emit_summary`/`emit_synthesis`/
  `emit_grouping`, `chunk.plan_chunks`/`needs_chunking`, настройки QualityBudget/overlap.
  ~2.5k строк удалено.
- **Изменена форма `Summary` (ломает старые `.json`).** Документ — это `synthesis` (фазы:
  heading + prose + anchors) + `main_themes` + `core_idea`; `Decision`/`ActionItem` получили
  `anchor`. Удалены `overview`/`key_takeaways`/`section_timecodes`/`recurring_themes`/`*_groups`
  и `SectionMarker`/`PointGroup`/`SectionGroup`.
- **Стоимость считается по K фазам (+1 reconcile при K>1)** через `cost.estimate_cost_synthesis`.
  TD-21: проекция вывода — не потолок API, а откалиброванная оценка на вызов
  (`[guard] output_tokens_estimate`, выверена по платному прогону до ~1.2× счёта, биас вверх).
  F6-guard проверяет КАЖДУЮ фазу до сети; вход держит отдельный «кириллица-вверх» биас.

### Добавлено

- **Пофазная проверка таймкодов — несущая часть ручного gate'а верности.** Каждый `[HH:MM:SS]`
  (в anchors, в прозе фазы, в decision/action, в шапке reconcile) сверяется с реальными
  таймкодами блоков ПОФАЗНО: точное совпадение принимается, в пределах 2с — подтягивается к
  ближайшему блоку, иначе отбрасывается. Таймкод фазы, совпавший лишь с блоком ДРУГОЙ фазы, —
  галлюцинация, и он отбрасывается (а не принимается по случайному совпадению).
- **Разные одинаково сформулированные пункты не схлопываются.** Фазы не перекрываются, поэтому
  decisions/actions просто конкатенируются — два разных пункта из разных фаз с одинаковым текстом
  больше не сливаются в один (свойство верности #4 «не сливать различия»).
- **Artifact-resume.** Каждая завершённая фаза пишется в `raw/.resume/<stem>.json`; повторный
  запуск дочитывает префикс и пропускает готовые фазы — включая случай, когда все K фаз сделаны,
  но reconcile/сохранение упали (тогда оплачивается только reconcile, не все фазы заново). Не
  job-движок: «фаза N на диске → пропустить».
- **Огрублены таймкоды транскрипта.** Whisper-сегменты склеиваются в блоки ~60 с
  (`config/models.toml` → `[transcript] block_seconds`): один `[HH:MM:SS]` на читаемый абзац
  вместо метки на каждую фразу. Таймкод блока — реальное начало его первого сегмента.
- **TD-18: связный мета-каркас заголовков.** `emit_reconcile` возвращает `phase_headings`, и
  пасс reconcile переписывает написанные «только-вперёд» заголовки фаз в один параллельный
  по форме план документа (`_apply_normalized_headings`, fail-soft при несовпадении числа/пустом).
  Заголовки не несут якорной фактической нагрузки, поэтому верность не страдает. K=1 оставляет свой.
- **TD-19: якоря вплетены в прозу, без сноски-стены.** Убран пофазный футер с перечнем таймкодов в
  PDF и MD; промпт синтеза вплетает несколько `[HH:MM:SS]` ВНУТРЬ прозы в точках, которые они
  подтверждают; полный массив `anchors` остаётся в `.json`. Якоря — это ссылки на момент в записи/
  MP3 (никуда не «кликать»), и валидатор гарантирует, что каждый указывает на реальный блок.
- **TD-20: типографика PDF.** Проход по типографике (титул 20pt + волосяная линейка, заголовки
  14pt, межстрочный 6.5, почти чёрные чернила) под читаемость длинного RU-резюме.
- **TD-12: новое меню «Что сделать?» для видео — MP3 как базовая дорожка.** Для видео меню теперь
  `MP3 only / Summary / Transcript / ← Back`: MP3 извлекается и СОХРАНЯЕТСЯ на каждой ветке (не
  тумблер и не комбо). Сбой извлечения для «MP3 only» фатален (возврат в меню), для Summary/
  Transcript — деградирует (предупреждение + продолжаем: оплаченное/основное важнее звука).
  Добавлена ветка «Transcript» (раньше для видео её не было — нельзя было получить транскрипт без
  оплаты резюме). Меню для `.mp3`-входа без изменений (`Summary / Transcript only`). Папка
  открывается по приоритету `summaries > transcripts > audio`; «Transcript» теперь открывает
  `transcripts`.

### Исправлено

- **Свежий прогон summarize-ит сам чекпойнт.** Обе ветки (свежий прогон и повторное резюме
  сохранённого `.txt`) подают модели байт-в-байт один и тот же таймкодированный транскрипт, так
  что anchors работают на обеих.

## [1.1.0] — 2026-06-25

### Добавлено

- **Решения и пункты к выполнению в резюме.** Структурированное резюме теперь выделяет
  отдельными разделами «Принятые решения» (решение + обоснование) и «Пункты к выполнению» в
  формате планирования: задача, ответственный и оценка трудозатрат. Для материалов без
  совещательной части (лекция, монолог) разделы пустые и не отображаются. Заголовки
  локализованы (RU/EN); оценка трудозатрат — экспертная прикидка модели, а не цитата из
  транскрипта.

### Исправлено

- **TD-6: заголовок резюме мог быть на языке источника.** Инструкция `title` в промпте усилена —
  заголовок всегда пишется на целевом языке резюме, даже если запись звучит на другом языке
  (закрепляется и в описании поля схемы). Ждёт платной live-перепроверки на кросс-языковом входе.
- **Шумный/нечитаемый транскрипт больше не превращается в правдоподобный мусор.** Промпт теперь
  распознаёт зацикленные галлюцинации Whisper (тишина/музыка) и возвращает пустое резюме с пометкой
  вместо выдуманного содержания.
- **Стабильный заголовок → нет дублей файлов.** Запрос к модели теперь идёт с `temperature=0`, так
  что повторный прогон того же файла даёт тот же заголовок (и перезаписывает результат, а не плодит
  `-2`/`-3`).
- **Единая подпись «не назначено».** Ответственный без имени получает один фиксированный ярлык на
  язык (`Не назначено` / `Unassigned`), а не случайную формулировку модели.
- **Ограничены объёмы списков.** `key_takeaways` — 3–7 пунктов, `recurring_themes` — 2–6 коротких
  фраз: длинные материалы больше не раздувают вывод (и счёт за токены).
- **Заголовки секций — на языке резюме**, даже если запись звучит на другом языке.

## [1.0.1] — 2026-06-25

Патч: две доработки консоли по итогам первых прогонов.

### Исправлено

- **Полоса прогресса при конвертации в MP3.** Извлечение дорожки из видео шло «вслепую» —
  одна строка и зависшая консоль до конца работы ffmpeg. Теперь конвертация показывает ту же
  полосу `%/ETA`, что и транскрипция: длительность определяется заранее, а прогресс считывается
  из ffmpeg на лету.
- **Папка результата открывается в Explorer для всех сценариев.** Раньше папка всплывала только
  после сохранения транскрипта. Теперь один раз за запуск открывается нужная папка по выбору в
  меню: `output/audio` после «MP3 only», `output/transcripts` после транскрипции. Окно открывается
  **в фоне**, не перехватывая фокус у консоли (`ShellExecuteW` + `SW_SHOWNOACTIVATE`).

## [1.0.0] — 2026-06-23

Первый релиз. EchoGist — консольный инструмент для Windows, запускаемый одним файлом:
берёт локальный аудио/видео файл (или сохранённый транскрипт) и выдаёт MP3-дорожку и/или
структурированное RU/EN резюме. Транскрипция — локально на GPU; резюме — один облачный
вызов Anthropic. Без логинов, онлайн-источников и истории.

### Возможности

- **Извлечение MP3** из локального видео/аудио (`imageio-ffmpeg`, без ручной установки ffmpeg).
- **Локальная GPU-транскрипция** через faster-whisper `large-v3` (`int8_float16`):
  авто-определение RU/EN, тайм-коды по сегментам, сохранение полного транскрипта.
- **Структурированное резюме** одним вызовом: о чём, ключевые выводы, тайм-коды по смысловым
  блокам, повторяющиеся темы, главная идея. Вывод в **PDF** (шрифт DejaVu, кириллица без «тофу»)
  или **Markdown**, на русском или английском.
- **Восстановление из транскрипта**: если облачный вызов сорвался (нет сети/ключа), транскрипт
  уже сохранён — резюме перегоняется без повторной транскрипции.
- **Контроль расходов**: локальная (офлайн) языко-зависимая оценка стоимости и подтверждение
  выше порога ($0.50 по умолчанию) до оплачиваемого вызова; фактическая стоимость — после.
- **Один `run.bat`**: идемпотентный первый запуск — venv, хеш-пиннутые зависимости, разовая
  загрузка модели, GPU-префлайт с понятной диагностикой.
- **Современная консоль** (questionary + rich): меню со стрелками, таблица настроек, полоса
  прогресса `%/ETA`, нативный выбор файла, навигация `← Back`, скрытый быстрый выбор 1–9,
  всплытие папки в Explorer после сохранения, панели результата/ошибки.
- **Настройки**: язык резюме, формат вывода, тариф модели (economy/balanced/flagship), порог
  стоимости — данные в конфиге, правятся без изменения кода.

### Архитектура и безопасность

- **Killswitch**: сетевой только этап `SUMMARIZE`; всё слева от него (включая оценку токенов и
  стоимости) — локально и офлайн, тестируется в CI против стаб-суммаризатора.
- **Чистые стадии** и **восстановление на артефактах** (сохранённый транскрипт = чекпоинт):
  ни `job.json`, ни слоя истории.
- **Ключ Anthropic** — только из `ANTHROPIC_API_KEY` или локального `config/secrets.toml`;
  никогда в коде и не коммитится.
- Гейт на каждый push в `main`: ruff + mypy --strict + тесты.
