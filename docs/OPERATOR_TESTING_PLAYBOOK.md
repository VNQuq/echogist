# EchoGist — Плейбук тестирования (для оператора)

**Для кого:** три запуска на Windows-машине с 4060, которые закрывают v1
(TD-3, TD-4, live-гейт T10).
**Где:** все запуски выполняются на **Windows-машине с 4060**, из корня
репозитория, в обычном `cmd` / PowerShell. Среда разработки WSL это сделать не
может (huggingface.co недоступен, нет загрузки GPU-модели, `ANTHROPIC_API_KEY`
там не задан).
**Как сообщать результат:** скопируй вывод консоли каждого запуска в наш чат.
Всё, что не является чистым PASS, — вставляй полную ошибку, не пересказывай.

Выполняй три запуска по порядку. Запуск 1 доказывает, что провижининг работает;
если он упал, остальные упадут так же — остановись и сначала покажи мне вывод
Запуска 1.

## Подготовка (один раз)

1. Открой консоль в корне репозитория (папка с `run.bat`).

2. Убедись, что ты на ветке `main` и дерево чистое:
   ```bat
   git status -sb
   ```
   Ожидается `## main...origin/main` и отсутствие неожиданных изменённых файлов.

3. Положи тестовые клипы в `tests\fixtures\audio\` (ни один не закоммичен):

   | Файл       | Что это                                                     |
   |------------|-------------------------------------------------------------|
   | `smoke.*`  | любой короткий клип (Запуск 1)                               |
   | `ru.*`     | ~3–5 мин русской речи, которую можешь оценить на слух (Запуск 2 — эталон для TD-4) |
   | `en.*`     | ~3–5 мин английской речи, контроль (Запуск 2)               |

   Подходит любой контейнер, который читает ffmpeg: `.mp3`, `.m4a`, `.wav`, `.mp4`, …

4. Задай API-ключ в этой консоли (нужен для live-вызовов в Запуске 2-опционально
   и Запуске 3):
   ```bat
   set ANTHROPIC_API_KEY=sk-ant-...
   ```
   > Ключ живёт только в переменных окружения. Никогда не клади его в файл или коммит.

## Запуск 1 — T13 win-smoke (закрывает TD-3)

**Что доказывает:** холодную приёмку на Windows — провижининг `run.bat` (venv +
установка с `--require-hashes` + загрузка модели + GPU-префлайт / загрузка DLL
cuDNN-cuBLAS), извлечение встроенным ffmpeg и реальную транскрипцию на GPU. Он
прогоняет `smoke.*` через extract→mp3 и transcribe→transcript и проверяет, что оба
артефакта созданы. Это единственный запуск, который задействует загрузку модели с
HF и загрузку GPU-DLL — то, что WSL проверить не может.

```bat
scripts\win-smoke.bat
```

**Ожидается:** запуск заканчивается строкой
```
[win-smoke] PASS — ship target works.
```

**Опционально** — прогнать ещё и единственный платный вызов SUMMARIZE целиком
(под killswitch, выполняется только когда заданы и переменная окружения, и ключ):
```bat
set ECHOGIST_LIVE_SMOKE=1
scripts\win-smoke.bat
set ECHOGIST_LIVE_SMOKE=
```

**Покажи мне:** полный вывод консоли, особенно строки провижининга и финальную
строку PASS/FAIL.

## Запуск 2 — T11 измерение (закрывает TD-4)

**Что доказывает:** A/B int8 против float16 на одной и той же модели (он
переключает `compute_type` на одном `model.bin`, без повторной загрузки) и
измеренный realtime_factor на твоей 4060.

> **Важно:** запускай через `scripts\measure.bat`, а НЕ `python scripts\measure_model.py`.
> faster-whisper стоит в `.venv`, а не в глобальном python — иначе будет
> «faster-whisper is not installed». Лаунчер сам берёт `.venv\Scripts\python.exe`.

**Шаг 2a — первый прогон, БЕЗ `--bar`** (отчёт всегда печатает измеренный
realtime_factor; порог ты выставляешь по нему уже после):
```bat
scripts\measure.bat --host "RTX 4060"
```

Он пишет отчёт в `docs\measurements\`. Из этого отчёта прочитай две вещи:

- **realtime_factor** — число скорости. Выбери по нему порог PASS
  (например, если намерило ~1.8, ставь `--bar 1.5`).
- **вывод int8 против float16 на RU** — оцени русскую транскрипцию обоих типов
  на глаз. Реши: **оставить int8** (быстрее, качество достаточное) или
  **перейти на float16** (медленнее, заметно лучше на RU).

**Шаг 2b — зафиксируй порог** и впиши свой вердикт:
```bat
scripts\measure.bat --host "RTX 4060" --bar 1.5
```
(подставь своё реальное число). Затем впиши свой вердикт оставить-int8/перейти-на-float16
в файл отчёта в `docs\measurements\`.

**Шаг 2c — закоммить отчёт:**
```bat
git add docs\measurements\
git commit -m "docs(T11): 4060 measurement + int8-vs-float16 verdict (closes TD-4)"
```

**Покажи мне:** измеренный realtime_factor, выбранный `--bar` и твой вердикт
int8/float16 (вставь отчёт или нужные строки).

## Запуск 3 — первый live-вызов API (гейт качества промпта T10)

**Что доказывает:** единственный реальный вызов суммаризации Anthropic — гейт
качества промпта, который пропускается в CI. Это те самые 2 теста, что сейчас
показаны как skipped. **GPU не нужен** — тест гоняет `summarize()` на готовых
RU/EN-транскриптах из `tests/fixtures/`, это чистый вызов API.

> **Важно:** `pytest` НЕ ставится в ship-venv (`run.bat` ставит только
> `requirements.lock` — рантайм). Поэтому Запуск 3 запускается в dev-среде,
> а не на ship-боксе. Два пути:

**Путь A (рекомендую) — из WSL** (там стоит весь dev-инструментарий):
```bash
cd ~/projects/echogist
ANTHROPIC_API_KEY=sk-ant-... ECHOGIST_LIVE_EVAL=1 .venv/bin/pytest -m live
```

**Путь B — на Windows**, если не хочешь идти в WSL: сначала поставь pytest в venv,
потом запусти его явно:
```bat
.venv\Scripts\python.exe -m pip install pytest
set ECHOGIST_LIVE_EVAL=1
.venv\Scripts\python.exe -m pytest -m live
set ECHOGIST_LIVE_EVAL=
```

**Ожидается:** 2 live-теста PASS (больше не skipped). Это первое доказательство,
что реальный вызов выдаёт структурированное RU/EN-резюме, проходящее scorer.

**Покажи мне:** итоговую строку pytest (например, `2 passed`) или полную ошибку,
если есть.

## Замечание о модели API

По умолчанию приложение теперь использует тариф **economy** (`claude-haiku-4-5`,
самый дешёвый: $1/$5 за миллион токенов вход/выход). Сменить тариф можно в
**Настройках** меню `run.bat`. Live-тест Запуска 3 жёстко зашит на тариф
`balanced` (Sonnet) в коде теста — это намеренно, чтобы гейт качества проверял
тот тариф, которому доверяешь; один прогон стоит копейки.
